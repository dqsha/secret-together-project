# Secret Together Project — контекст для Claude

Этот файл Claude Code читает при каждом запуске. Это сжатая «память» проекта: всё, что обсуждали в первом чате (ноябрь 2026), и правила совместной работы. **Отвечай пользователю по-русски, коротко, сначала главное.**

## Что это
Онлайн-бронь столов для заведения в **Актобе (Казахстан)** — лаунж/караоке с общим залом и двумя VIP-комнатами. Две части:

| Папка | Что | Кто отвечает |
|---|---|---|
| `booking/` | Приложение бронирования: гость выбирает стол на схеме, хостес видит брони | друг (гостевые вкладки, хостес) |
| `editor/` | Отдельный редактор схемы зала (мебель, столы, стулья) | dqsha (владелец репозитория) |
| `shared/plan.json` | Схема зала — **общий контракт** между частями | оба, по договорённости |
| `docs/business/` | Бизнес-план, цена, конкуренты, план запуска | справочно |

Обе части — **одностраничные HTML-файлы без сервера и без фреймворков** (чистый JS + SVG). Данные пока хранятся в `localStorage` браузера. Сервера нет — это главный открытый вопрос (см. «Что дальше»).

## Как собрать и проверить
```
pip install pillow playwright && playwright install chromium
python3 booking/build.py     # -> dist/booking.html
python3 editor/build.py      # -> dist/editor.html
./tests/run_all.sh           # сборка + все тесты (эмуляция iPhone 13)
```
- Правь **`*/template.html`**, а не `dist/` — `dist/` пересобирается.
- В шаблонах есть плейсхолдеры `__PLAN__` (схема из `shared/plan.json`) и `__PH__` (фото из `booking/assets/photos`, вставляются как base64).
- `booking/build.py` заменяет CSS `light-dark()` на переменные — старые iPhone (iOS < 17.5) его не понимают. Можно писать `light-dark()` в шаблоне.
- После изменений: собрать, прогнать тесты, открыть `dist/*.html` на телефоне.

## Формат схемы (`shared/plan.json`) — контракт
Подробно: `docs/plan-format.md`. Кратко:
- `zones[]`: `{id, name, h}` — залы. Ширина всех залов **360** единиц, высота `h`.
- `tables[]`: `{id, n, zone, x, y, w, h, shape:'rect'|'round', seats, join[], photo, desc, deposit, rot?, ch?, lock?}`. `x,y` — **центр**. `seats` — вместимость для брони. `join` — с какими столами можно сдвинуть (симметрично).
- `decor[]`: `{id, z, t, x, y, w, h, rot, label, col?, fs?, shape?, lock?}` — мебель и стены, `t` — тип.
- **Новое из редактора (booking пока НЕ умеет):** `rot` с любым углом у столов и мебели; `ch:0` у стола = «стулья не рисовать автоматически, они лежат в decor как `t:'chair'`»; новые типы decor: `door, window, column, stairs, sofaL, booth, armchair, pouf, chair, host, zone, stage, rug, plant, tv` и цвета `col`.
- Перенос схемы между приложениями: редактор «⋯ → Скопировать текст схемы» → в booking «Ещё → Схема → Вставить схему».

## Решения и пожелания пользователя (не ломать)
**Дизайн:** «Liquid Glass» — полупрозрачные стеклянные панели (`.glass`), круглые иконки-линии (`ICONS` + `ic()`), зелёный акцент `--em`, светлая и тёмная тема. Всё должно быть удобно **с телефона** (кнопки ≥ 44px).

**Гость (booking):** календарь для даты + колесо времени; вопрос «Сколько человек?» (НЕ «Сколько будете»); нажал стол → сразу шаг с данными; заметные кнопки «Назад»; телефон сам начинается с `+7`; одна кнопка «Повод», по умолчанию «Без повода» (список поводов включает казахские: Кыз узату, Тусау кесер, Сундет той, Наурыз).

**Хостес (booking):** вход по PIN (по умолчанию 1234); статусы брони, таймлайн, пересадка за другой стол, продление, гости без брони (walk-in), поиск свободного стола, объединение столов для компаний; счётчики броней видны сразу; брони по дням «колонками»; даты через календарь; без мерцания (DOM обновляется через `morph()` по `data-id`).

**Редактор (editor):**
- Сначала **нажать — выделить**, двигать можно только выделенный (свайп по невыделенному = листать зал). Долгое нажатие — сразу тащить. Двойное — «Детали».
- Ручки растягивания и кнопка поворота; у мелких предметов ручек нет, вместо них **джойстик** снизу (появляется сам).
- «Замена» — поменять предмет на любой из библиотеки с сохранением места и поворота.
- **Столы и стулья — раздельно.** Новый стол без стульев; «Поставить N стульев вокруг», «Выделить со стульями»; «Несколько стульев сразу» (ряд/рядами/полукруг/круг).
- Замок, копия, выравнивание, отмена/возврат, сетка и примагничивание, предупреждение о пересечениях, несколько залов.

## Технические мелочи, на которых уже обжигались
- Бизнес-день идёт через полночь (заведение до 02:00): `toAbs()`, `bizToday()` в booking.
- `history.replaceState` и `localStorage` могут быть запрещены (Safari, превью в песочнице) — всё обёрнуто в try/catch (`setHash`, флаг `LS`). Не убирать.
- В редакторе жесты — Pointer Events с захватом на `<svg id="cv">`; во время перетаскивания мир перерисовывается через `rafWorld()`.

## Бизнес-контекст (кратко, подробно в `docs/business/`)
- Цена для заведений: **9 900 ₸/мес** (тарифы 9 900 / 14 900 / 24 900), первый месяц и настройка бесплатно, «цена основателя» для первых 10 заведений.
- Безубыточность ~4 платящих заведения. Вердикт проверки идеи: **«пока рано продавать»** — спрос не подтверждён живыми людьми, нет сервера.
- Конкуренты: Restoplace, Saby Presto, Halyk Рестораны, Gourmet, Tabley; главный заменитель — тетрадь + WhatsApp.
- По закону РК персональные данные гостей должны храниться на сервере **в Казахстане**.

## Что дальше (очередь задач)
1. **booking: научиться рисовать схему как редактор** — `rot`, `ch:0` (не рисовать точки-места), новые типы мебели и цвета. Лучше вынести рисование в общий модуль, чтобы не дублировать. *Без этого схема из редактора в booking выглядит неправильно.*
2. Сервер в Казахстане: аккаунты, общая база гостя и хостес, резервные копии.
3. Подтверждения и напоминания гостям в WhatsApp.
4. Банкеты/тои с предоплатой по ссылке Kaspi, статистика неявок.
5. Работа без интернета с досылкой.
